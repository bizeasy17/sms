# 前台首页研究页面设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 页面名称 | 股票研究首页 / 研究工作台 |
| 参考设计 | `docs/requirements/ui/stock-research-workspace_lean.html` |
| 前端项目 | `manniu/manniu_frontend` |
| 技术栈 | React 19、TypeScript、Vite |
| 页面定位 | 登录用户进入系统后的股票研究主工作区 |
| 设计目标 | 模块化、样式统一、信息克制、适配桌面与小屏幕 |

本页面是研究流程的入口，不承担营销展示和复杂配置。用户进入页面后，应能快速完成三件事：

1. 从覆盖池、持仓、自选或观察列表中选择股票。
2. 查看当前股票的研究结论、估值状态和基本面证据。
3. 进入技术趋势、基本面、财报档案等更详细的研究模块。

## 2. 设计原则

### 2.1 模块化

页面由稳定的功能模块组成，每个模块拥有清晰的输入、输出和加载状态。模块之间通过股票上下文和筛选上下文连接，避免在一个页面组件中堆叠业务判断。

推荐的模块边界：

- `AppShell`：全局页头、导航、用户菜单和页面容器。
- `StockRail`：股票池、筛选条件和股票选择。
- `ResearchDossier`：当前股票的研究主体内容。
- `StockIdentity`：股票名称、代码、行业、最新价格和涨跌幅。
- `ResearchTabs`：研究摘要、技术趋势、基本面、财报档案等页签。
- `ThesisStrip`：当前判断、研究摘要和仓位建议。
- `ValuationSummary`：综合内在价值、估值区间和估值方法。
- `MarketEvidence`：价格趋势、波动率、相对强度等市场证据。
- `FundamentalEvidence`：营收、毛利率、ROE、经营现金流等基本面指标。
- `ResearchEvents`：财报、模型信号、技术变化和行业事件。
- `ResponsiveStockDrawer`：手机端股票列表抽屉。

组件只负责展示和交互，数据请求、缓存和错误重试放在页面级数据 hooks 或 service 层中。

### 2.2 统一样式

所有研究页面共用以下视觉语言：

- 背景使用低对比度冷灰色，内容区域使用白色，形成清晰但克制的层级。
- 主色使用研究蓝，用于选中态、主操作、链接和趋势线。
- 涨跌颜色遵循 A 股统一约定：上涨、正向收益使用红色，下跌、负向收益使用绿色，平盘使用中性灰；该规则适用于研究首页及所有前台研究模块。
- 不使用大面积紫色渐变、强装饰插画或营销型 Hero 区域。
- 卡片只用于独立的指标组、弹窗和事件项；页面主要区域使用无嵌套卡片的分区布局。
- 圆角保持轻量，默认不超过 `8px`；按钮、输入框和标签使用小圆角。
- 数值、股票代码、日期和接口字段使用等宽字体，保证扫描和对齐。
- 中文正文使用项目统一 sans 字体；研究结论可以使用少量衬线字体作为层级强调，但不能影响可读性。

### 2.3 极简信息表达

- 首屏优先展示“现在应该怎么看这只股票”，而不是展示全部数据。
- 每个区块只保留一个主标题、一个辅助时间或状态、一个核心动作。
- 指标默认展示最新值和单位，历史趋势通过图表或二级页面查看。
- 状态标签使用短词，例如“传统低估”“模型高位”“财报待更新”。
- 不在页面中展示冗长的功能说明、快捷键说明或设计解释性文字。
- 数据不可用时展示原因和下一步动作，不用空白区域伪装成正常状态。

### 2.4 小屏幕优先保证任务完成

手机和 iPad 不是桌面布局的简单缩小版。小屏幕应保留股票切换、研究结论、估值结论和关键指标，其余信息按优先级折叠或下沉。

## 4. 页面布局

### 4.1 桌面端（大于 1050px）

采用三列布局：

- 左侧股票栏：约 `238px`，固定在页面左侧的独立容器中，并在容器内部独立滚动；页面主内容滚动时股票栏位置不变。
- 中间研究主体：自适应宽度，最大内容宽度约 `1100px`。
- 右侧事件栏：约 `292px`，展示研究事件和待验证事项。
- 页头固定在顶部，高度约 `56px`。
- 主体顶部预留页头高度，滚动时不被页头遮挡。

中间主体的研究内容按纵向分区排列，不使用过多浮动卡片。估值区和证据区可以使用网格布局，但各分区之间使用细分隔线建立节奏。

### 4.2 iPad / 中等屏幕（701px 至 1050px）

采用两列布局：

- 左侧股票栏缩减到约 `200px`，仍使用固定容器并独立滚动。
- 研究主体占据剩余空间。
- 右侧事件栏隐藏，事件内容可通过研究摘要中的入口或底部区域访问。
- 估值方法和证据指标允许从双列变为单列，避免单元格内容拥挤。
- 股票栏保持可滚动，主内容保持正常纵向滚动。

### 4.3 手机端（不大于 700px）

采用单列布局：

- 页头固定，高度约 `52px`。
- 左侧股票栏变为从左侧滑出的抽屉，不占用主内容宽度。
- 页头显示菜单按钮、品牌标识、搜索入口和用户入口。
- 研究主体使用左右内边距 `16px`。
- 研究页签保持单行横向滚动，不换行。
- 右侧事件栏隐藏；事件可作为摘要区的可折叠列表或后续独立页面。
- 估值区、市场证据区、基本面证据区全部单列。
- 指标网格使用两列；当内容较长或字体放大时自动降为一列。
- 股票切换后自动关闭抽屉，保持用户上下文连续。
- 点击遮罩或返回键关闭抽屉；菜单按钮同步更新 `aria-expanded`。

## 5. 模块设计

### 5.1 TopBar

**职责**：提供全局身份、主导航、搜索和账户入口。

**内容**：

- 品牌标识：`ManNiuNiu` 或系统正式品牌名。
- 全局导航：研究、选股；当前页面使用选中态。
- 搜索：支持公司名称、股票代码、主题关键词。
- 用户菜单：展示当前用户、注销入口。

**交互要求**：

- 搜索框支持键盘聚焦和回车提交。
- 未登录状态跳转登录页，不渲染研究数据。
- 用户菜单可通过点击打开，点击外部区域关闭。
- 手机端隐藏文字导航，只保留菜单按钮和搜索入口。

### 5.2 StockRail

**职责**：选择研究股票并快速切换股票集合。

**顶部筛选**：

- 顶部使用单行筛选栏，组合按钮与市场下拉菜单属于同一层级。
- 组合按钮依次为：持仓、自选、观察；当前组合使用研究蓝文字、浅蓝背景和明确焦点状态。
- “全部市场”放在筛选栏最右侧，使用原生可聚焦的下拉菜单，不与组合按钮拆成上下两行。
- 下拉菜单默认显示“全部市场”；打开后的子菜单内容固定为：沪主板、深主板、创业板、科创板。选择具体市场后列表只展示对应市场股票，重新选择组合时可恢复“全部市场”。
- 市场下拉菜单应提供 `aria-label`、当前选中值和键盘操作支持，点击外部区域或按 `Escape` 可关闭菜单。
- 筛选栏在可用宽度不足时保持控件可读：市场菜单可收窄，但不得遮挡组合按钮或产生横向溢出。

**股票卡片信息**：

- 卡片保留股票名称、股票代码、所属行业和涨跌信息，字段顺序与当前研究页面一致。
- 卡片底部固定展示两个标签，顺序保持不变：第一个为基本面估值标签，第二个为模型估值标签。
- 标签内容绑定后台研究结果，格式为“价值 - {action} · {score}分”和“模型 - {action} · {score}分”；例如“价值 - 买 · 82分”“模型 - 持 · 62分”。
- 价值标签的 `action` 和 `score` 分别来自 `traditional_valuation.action`、`traditional_valuation.undervalue_score`；模型标签分别来自 `predictive_valuation.action`、`predictive_valuation.undervalue_score`。两个低估分均按四舍五入保留整数展示。
- 外层标签的字体、边框、圆角和其他视觉风格保持统一灰色样式；仅标签内部的 action 和 score 文字着色：`BUY` 显示为红色“买”，`SELL` 显示为绿色“卖”，`HOLD` 显示为蓝色“持”，分数沿用对应 action 的文字颜色。
- 前端不得根据价格、涨跌或其他指标自行推导动作或估值分；估值对象为空时标签只显示“价值 - 暂无”或“模型 - 暂无”，部分字段缺失时只展示实际存在的字段，不能使用默认值伪造结果。
- 当前股票卡片使用浅蓝背景和左侧研究蓝标识线；键盘聚焦、悬停和禁用状态必须清晰可见。
- 股票卡片加载时使用与正式卡片相同高度和信息层级的骨架屏；无数据时明确显示“暂无股票”，并提供进入自选或添加股票的动作。

**固定容器与滚动**：

- 桌面端和 iPad 端 `StockRail` 使用固定宽度容器，固定在页头下方；股票列表区域在容器内部独立纵向滚动。
- 固定容器不得随研究主体纵向滚动离开视口，也不得覆盖页头、主内容或右侧事件栏。
- 股票筛选栏保持在股票容器顶部可见，列表滚动时不随列表内容一起移出；筛选栏与列表之间使用分隔线建立层级。
- 手机端不使用常驻固定栏，改为左侧抽屉；抽屉打开时仍复用同一套筛选栏、市场下拉菜单和股票卡片。

**股票项**：

- 股票名称。
- 股票代码和行业。
- 最多展示两个短状态标签。
- 当前股票使用浅蓝背景、左侧蓝色标识线。
- 股票列表加载时使用与列表结构一致的骨架屏。
- 无数据时明确显示“暂无股票”，并提供进入自选或添加股票的动作。

**数据行为**：

- 切换筛选条件只刷新列表，不清空当前研究主体，直到用户选择新股票。
- 选中股票后更新路由或 URL 查询参数，支持刷新和分享后恢复上下文。
- 列表请求失败时保留上一次列表，并展示轻量错误提示和重试按钮。

### 5.3 StockIdentity

**职责**：确认用户当前研究对象。

**内容**：

- 面包屑：覆盖池 / 行业 / 个股研究。
- 股票名称和交易所代码。
- 行业、覆盖状态、数据周期。
- 最新价格、涨跌额和涨跌幅。

**规则**：

- 价格与涨跌幅使用等宽数字字体。
- 上涨使用 A 股红色，下跌使用 A 股绿色，平盘使用中性灰；颜色必须同时配合涨跌符号或文字，不能只依靠颜色表达状态。
- 数据时间必须明确，例如“数据截至 2026-08-17”。
- 数据延迟或非交易时段应显示状态，不把旧数据伪装为实时数据。
- 头部基本信息卡片不展示“已覆盖”状态，保留行业、数据周期、最新价格和涨跌信息。

#### 5.3.1 行情接口接入契约

用户单击左侧股票列表中的股票后，研究页头部行情从以下接口加载，不使用前端静态价格或涨跌值：

```text
GET /api/v1/market-analysis/securities/:ts_code/bars
  ?start_date={YYYY-MM-DD}
  &end_date={YYYY-MM-DD}
  &adjust=qfq
  &frequency=D
  &page=1
  &page_size=200
```

- `:ts_code` 使用股票列表返回的标准交易代码，例如 `002236.SZ`。
- `start_date` 和 `end_date` 默认覆盖最近一年；`end_date` 使用当前日期，不把示例日期写死在前端。
- 头部只使用响应 `data` 中 `trade_date` 最新的一条记录：`close` 展示最新价格，`change` 展示涨跌额，`pct_change` 展示涨跌幅，`trade_date` 展示数据截至日期。
- `data` 数组为空时，股票名称、代码和行业仍保留，价格区域显示“暂无行情”和“数据暂无”，不能使用 `0` 或静态默认值。
- 请求失败时保留股票身份信息，价格区域显示“行情加载失败”，并提供局部重试动作；失败不应清空股票列表或其他研究模块。
- 切换股票时取消或忽略上一次 bars 请求，禁止旧股票行情覆盖当前股票头部。
- 接口响应沿用统一响应包装：`data` 为日线记录数组，`meta.data_status` 表示 `COMPLETE` 或 `NO_DATA`；每条记录至少包含 `ts_code`、`trade_date`、`close`、`change`、`pct_change`、`adjust` 和 `frequency`。

示例响应：

```json
{
  "data": [
    {
      "ts_code": "002236.SZ",
      "trade_date": "2026-09-17",
      "close": 24.68,
      "change": 0.45,
      "pct_change": 1.84,
      "adjust": "qfq",
      "frequency": "D"
    }
  ],
  "meta": {
    "data_status": "COMPLETE",
    "asof_date": "2026-09-17"
  }
}
```

### 5.4 ResearchTabs

默认页签：

1. 研究摘要
2. 技术趋势
3. 基本面
4. 财报档案

页签规则：

- 页签是导航，不承担复杂筛选。
- 当前页签以蓝色文字和底部线标记。
- 桌面端使用横向排列；手机端单行滚动。
- 页签切换应保持股票上下文和筛选上下文。
- 具体子页可按相同 `AppShell` 和 `StockIdentity` 复用，不另起视觉体系。

### 5.5 ThesisStrip

**职责**：在首屏给出研究结论和行动倾向。

**内容**：

- 当前判断，例如“中性持有”。
- 一句话核心论点。
- 一句较短的证据补充。
- 仓位建议或信心分数。

**规则**：

- 结论必须来自后端研究结果，不在前端推导。
- 核心论点限制为两行左右，超出部分折叠或进入详情。
- “中性持有”等判断使用文本和色彩同时表达，不能只依靠颜色。
- 研究结论缺失时显示“暂无研究结论”，不能显示默认持有建议。

### 5.6 ValuationSummary

**职责**：回答“当前价格是否合理”。

**内容**：

- 综合内在价值区间：保守值、中枢值、乐观值。
- 估值区分为两个独立模块：上方为 `01.1 / FUNDAMENTAL VALUATION` 基本面估值，下方为 `01.2 / MODEL VALUATION` 模型估值。
- 两个模块均展示完整估值摘要结构，包括模块头部文案、`Current View` 研究结论、估值高低 bar、当前价格位置和右侧估值模型列表。
- `01.1 / FUNDAMENTAL VALUATION` 使用“基本面估值摘要”文案，直接展示传统估值接口返回的多个方法；不得硬编码“盈利预测”或用静态方法替代后台结果。
- `01.2 / MODEL VALUATION` 使用“模型估值摘要”文案，展示预测模型和融合模型等模型估值结果，不再使用“模型估值 / 待定”占位文案。
- 当前价格在估值区间中的位置。
- 估值方法列表，例如 PE、FCFF、盈利预测。
- 每个方法的估值结果、偏离幅度和判断。
- 数据时间和模型数量。

**视觉规则**：

- 估值区间使用一条从深绿色、浅绿色、浅红色到红色的连续渐变色带，依次表达低估、合理到高估。
- 当前价格使用单一指针标识，避免同时出现多个强指针。
- 游标价格标签放在游标圆点下方，靠近圆点但不与估值色带上的价格刻度重叠。
- 方法列表使用分隔线对齐，不做多层卡片嵌套。
- 估值结果和涨跌数值使用等宽字体。

**模型估值展示**：

- 模型估值作为与基本面估值并列的独立模块展示，使用独立的 `01.2 / MODEL VALUATION` 模块标题。
- 模型模块沿用基本面模块的估值区间、当前价格指针、状态表达和异常处理规范，但模型方法列表单独维护。

**异常状态**：

- 某一估值方法失败时显示“暂不可用”，不影响其他方法展示。
- 没有足够模型时展示样本数不足提示。
- 估值日期过期时展示数据更新时间和刷新动作。

**传统估值接口接入契约**：

研究页选中股票后调用：

```text
GET /api/v1/market-analysis/securities/:ts_code/valuations/traditional
  ?asof_date={YYYY-MM-DD}&include_methods=true&include_risk=true
```

前端使用响应的 `current_price`、`summary.composite_valuation_price_optimized`、
`summary.conservative_valuation_price_optimized`、
`summary.traditional_tiered_template.aggressive.target_price`、`risk.confidence`、
`risk.risk_level` 和 `methods` 渲染传统估值卡片。`methods` 中每条记录的
`valuation_method`、估值价格和不可用原因原样保留；不得补零、推导盈利预测或把
接口缺失改成默认估值。接口失败、权限不足或没有已发布结果时，卡片显示对应的
局部异常状态，不影响行情和基本面区块。

信心分数下方固定显示“风险级别 高/中/低”，没有风险结果时显示“暂无”。
保守、中枢、乐观区间的当前价格指针使用区间比例，并将比例限制在 `0%..100%`；
当当前价格低于保守价或高于乐观价时，价格标签仍显示真实值，但指针停留在色带
端点，不得飞出 bar 范围。传统估值方法列表不显示前端静态“盈利预测”项，后台返回
的多个方法均按返回顺序展示。`include_methods=true` 和 `include_risk=true` 只需
`market_analysis:read`；只有显式请求 `include_diagnostics=true` 时才需要
`valuation:diagnostics_read`。

### 5.7 MarketEvidence

**职责**：展示市场正在交易的主要证据。

**内容**：

- 近 60 个交易日趋势图。
- 14 日波动率及历史分位。
- MA60 趋势。
- 相对行业强度。
- 筹码集中度或其他已确认的市场指标。

**图表规则**：

- 图表默认只展示一条主要价格趋势和一条对照趋势。
- SVG 折线图增加 10 分位、中位数、90 分位三条水平参考线，并在图例或标注中明确含义。
- 图表必须有空状态、加载状态和无足够数据状态。
- 图表颜色与全局状态颜色统一。
- 不在移动端强行显示过多坐标轴文字，保留趋势和关键值即可。
- 图表容器使用稳定高度，避免加载前后页面跳动。

### 5.8 FundamentalEvidence

**职责**：展示最新财报的关键基本面指标。

默认指标：

- 营收增速。
- 毛利率。
- ROE。
- 经营现金流。
- 净利润绝对值及同比。
- EBIT 绝对值及同比。
- 净利率绝对值及同比。
- 负债率绝对值及同比。

规则：

#### 5.8.1 财务基本面接口接入契约

研究首页选择股票后，基本面区调用：

```text
GET /api/v1/market-analysis/securities/:ts_code/financials/overview
  ?asof_date={YYYY-MM-DD}&report_type=LATEST
```

前端直接展示接口返回的 `metrics`，不再使用静态样例或自行计算同比、
rolling12。每个指标读取 `value` 为当前报告期绝对值/比例、`yoy` 为同比、
`rolling12` 为滚动 12 个月值，并同时展示 `period` 和单位元数据。金额类指标
展示收入、经营现金流、净利润、EBIT；比例类指标展示毛利率、ROE、净利率、负债率。
后端当前以 `income.operate_profit` 作为 EBIT 来源，前端按接口 key 展示，不改名或推导。

接口状态为 `NOT_AVAILABLE` 或指标 `available=false` 时展示“暂无数据”，不得显示 0；
请求失败时只影响基本面模块，保留股票身份、行情和其他研究模块，并提供重试动作。

- 每个指标包含名称、值、单位和同比或环比说明。
- 指标卡不展示无法解释的综合分数。
- 指标缺失时展示“暂无数据”和所属报告期。
- 金额类指标明确单位，禁止把百分比、金额和次数放在同一格式中。
- 净利润和 EBIT 使用绝对值展示，并在同一指标项的辅助文字中展示同比；格式与现有基本面指标一致。
- 净利率和负债率使用百分比绝对值展示，并在同一指标项的辅助文字中展示同比或百分点变化；格式与现有基本面指标一致。
- 四列仅用于宽屏；iPad 使用两列，手机默认两列，内容较长时单列。

### 5.9 ResearchEvents

**职责**：按时间展示影响研究判断的事件。

事件类型：

- 财报更新。
- 模型信号变化。
- 技术趋势变化。
- 行业跟踪。

每条事件包含日期、类型、标题和一段说明。右侧栏底部提供“需要验证”区域，列出海外渠道、毛利率、应收账款等待确认事项。

在中小屏幕上，事件栏不占据首屏宽度。可将事件入口放在研究摘要底部，使用可折叠区域呈现。

## 8. 数据与状态约定

页面至少需要以下状态：

- `loading`：首次请求或切换股票时显示结构化骨架屏。
- `ready`：正常展示研究数据。
- `partial`：部分模块成功，失败模块独立提示。
- `empty`：当前股票没有足够研究数据。
- `error`：页面级请求失败，保留可重试动作。

建议的页面上下文：

```ts
type ResearchContext = {
  tsCode: string
  tab: 'summary' | 'technical' | 'fundamental' | 'financials'
  stockPool: 'holding' | 'watchlist' | 'observe' | 'market'
  market?: 'sh' | 'sz' | 'cyb' | 'star'
}
```

前端只负责展示和传递后端结果：

- 不在组件内重新计算估值结论、评分或仓位建议。
- 所有金额、百分比和比率从接口元数据或明确字段中读取单位。
- 接口响应缺少字段时使用局部空状态，不使用 `0` 伪造有效数据。
- 切换股票时取消或忽略上一次尚未完成的请求，避免旧股票数据覆盖新股票。
- 数据时间、报告期和更新时间必须与数据一同展示。

## 9. 交互与无障碍要求

- 股票项、页签、筛选项、按钮都必须使用原生可聚焦元素。
- 图标按钮提供 `aria-label`，不能只依赖图形含义。
- 抽屉打开时将焦点移入抽屉，关闭后恢复到菜单按钮。
- 颜色不是唯一状态表达方式，状态同时使用文字、图标或边框。
- 键盘可完成股票筛选、股票选择、页签切换和抽屉关闭。
- 所有可点击元素提供明显的 hover、focus-visible 和 disabled 状态。
- 动画只用于抽屉、加载和轻量状态变化；支持 `prefers-reduced-motion`。
- 正文和数据文字满足可读对比度，辅助文字不能因颜色过浅而无法识别。

## 10. 路由与 URL 状态

建议首页使用 `/research`，当前股票和页签写入 URL：

```text
/research?ts_code=002236.SZ&tab=summary&pool=watchlist
```

要求：

- 刷新页面后恢复当前股票和页签。
- 通过浏览器前进、后退可以恢复研究上下文。
- 股票不存在或用户无权访问时显示明确错误页，并提供返回股票池动作。
- 未登录用户跳转统一登录页，登录成功后回到原始研究 URL。
