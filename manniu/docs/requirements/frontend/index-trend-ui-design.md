# 指数趋势弹窗前台设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 页面名称 | 指数趋势 |
| 页面形态 | TopBar 入口打开的弹窗工作区 |
| 前端项目 | `manniu/manniu_frontend` |
| 技术栈 | React、TypeScript、Vite |
| 入口位置 | TopBar 的“选股”右侧，同级导航“指数趋势” |
| 主要数据 | 7 指数综合基本面、上证综指基本面 |
| 当前阶段 | 先完成设计，后续再实现页面和接口接入 |

本页面参考旧项目的“综合综合指数趋势”截面，服务于快速判断市场整体估值位置和上证综指自身估值位置。页面只展示已经由后台计算好的序列、分位和状态，不在浏览器重新计算权重、分位、P10/P50/P90 或估值结论。

## 2. 设计目标与边界

### 2.1 目标

- 从任意前台页面快速打开指数趋势，不离开当前研究上下文。
- 同屏对比“7 指数 overall 综合基本面”和“上证综指基本面”。
- 支持 `PE`、`PETTM`、`PB`、风格和时间窗口切换。
- 首屏直接回答：当前值、数据日期、历史分位、P10/P50/P90 以及趋势位置。
- 在数据不足、部分指数缺失、接口失败时明确表达状态，不显示伪造曲线。

### 2.2 不负责

- 不在前端计算 7 指数权重、共同交易日、分位或估值价格。
- 不调用 Tushare 或其他外部数据源。
- 不提供交易指令、买卖建议或用户配置持久化。
- 不把上证接口返回的数据冒充为综合指数数据。

## 3. TopBar 入口

### 3.1 导航结构

桌面端 TopBar 顺序保持为：

```text
品牌 | 研究 | 选股 | 指数趋势 | 搜索 | 用户入口
```

- 文案固定为“指数趋势”。
- 使用与“研究”“选股”相同的导航样式和 active 状态。
- 入口使用按钮或链接语义，不能使用纯文本点击区域。
- 打开弹窗时，“指数趋势”进入 active 状态；关闭后恢复原页面 active 状态。
- 不改变当前页面 URL，不清空当前选中的股票、筛选条件或研究状态。
- 支持 `Enter`、`Space` 打开，弹窗打开后 `Escape` 关闭。

移动端 TopBar 空间不足时保留一个带 `aria-label="打开指数趋势"` 的图标按钮，并提供 tooltip“指数趋势”；不得与公司搜索输入框重叠。

### 3.2 弹窗行为

- 弹窗覆盖视口内容，TopBar 保留在视觉层级上方或由弹窗统一接管焦点。
- 桌面端弹窗宽度约为视口的 `min(1420px, calc(100vw - 48px))`，高度约为 `min(820px, calc(100vh - 40px))`。
- 背景使用半透明遮罩；弹窗主体为白色、轻量边框和不超过 `8px` 圆角。
- 弹窗主体内部独立滚动，页面背景禁止滚动。
- 打开时焦点进入关闭按钮；关闭后焦点返回“指数趋势”入口。
- 图表、摘要和控制器必须有稳定尺寸，加载前后不能造成弹窗跳动。

## 5. 页面视觉和交互

### 5.1 顶部控制区

- 弹窗标题使用紧凑标题，不使用营销型 Hero。
- “综合指数 / 上证分位”使用 segmented control，默认选中“综合指数”。
- `PE`、`PETTM`、`PB` 使用 segmented control，默认 `PE`。
- 风格当前显示为只读的“综合”，对应后台 `overall`；防御/平衡/进攻保留为后续扩展，不在本期发送请求。
- 时间窗口使用紧凑 tab，默认 `1Y`；“所有”映射后台 `ALL`。
- 任何控制器变更都触发两个数据区同步刷新，并保留当前控制器状态。
- 请求进行中时保留旧图但覆盖轻量 loading 状态，禁止显示旧标题配新数据。

### 5.2 摘要条

参考截图，摘要条展示：

```text
综合指数 PE 最新值 25.83   日期 2026-09-22   1Y 分位 48.4%
P10 24.85   P50 25.89   P90 27.39
```

- 数值、日期、百分比使用等宽字体。
- `current`、`percentile`、`p10`、`p50`、`p90` 均来自接口 summary。
- 后端缺失某字段时显示“暂无”，不得显示 0、100 或最近一次旧值。
- 摘要中必须显示 `data_status` 对应的短状态：完整、部分数据、样本不足、暂无数据或请求失败。
- 本阶段不展示截图中的“组合估值/保守估值”，因为指定综合接口是基本面序列接口；除非后端另行提供估值字段，不在前端推算。

### 5.3 趋势图

- 综合区和上证区各使用一张独立折线图，默认按接口 `series` 的交易日升序绘制。
- 主线使用研究蓝；P10、P50、P90 使用细虚线，并在右侧标注对应名称。
- 正常状态下主图展示一条估值指标线，不叠加未经接口提供的“市场情绪”示例线。
- 横轴显示交易日期，tooltip 至少包含交易日、指标名称、指标值和当前窗口状态。
- 图表支持缩放和 hover 十字线；缩放只影响视图，不重新请求或改变分位口径。
- 无数据时保留图表固定高度，显示局部空状态；不能渲染空坐标轴伪装为有效走势。
- `PARTIAL` 或缺少指数时，图表继续展示后台返回的合法综合序列，并在图下显示缺失指数和 warning。

### 5.4 响应式布局

- 桌面端：上下两个趋势区，各占主要高度；摘要和控制器固定在弹窗顶部。
- 平板端：保持上下排列，减少横轴标签密度，tooltip 仍可查看完整日期和值。
- 手机端：弹窗改为近全屏抽屉式布局；控制器允许横向滚动但页面整体不得横向溢出；综合区和上证区上下单列。
- 关闭按钮、控制器文字和图表标注不得相互遮挡；长状态文案允许换行。

## 6. 数据接口契约

### 6.1 综合指数基本面

固定调用：

```http
GET /api/v1/market-analysis/indices/composite/fundamentals?metric=PE
```

实际请求参数：

| 前端状态 | 参数 |
| --- | --- |
| 指标 | `metric=PE` / `PETTM` / `PB` |
| 时间窗口 | `window=30D` / `60D` / `90D` / `1Y` / `3Y` / `5Y` / `10Y` / `ALL` |
| 明确日期范围 | `start_date` + `end_date`，与 `window` 互斥 |
| 风格 | 不发送；接口固定使用 `overall` |

前端主要读取：

| 响应字段 | 用途 |
| --- | --- |
| `data.metric` | 当前指标名称 |
| `data.style` | 显示为综合/overall，作为校验信息 |
| `data.series` | 综合趋势线，日期键值序列 |
| `data.summary.current` | 最新值 |
| `data.summary.percentile` | 当前分位 |
| `data.summary.p10/p50/p90` | 分位参考线和摘要 |
| `data.summary.start_date/end_date` | 窗口实际边界 |
| `data.summary.sample_count` | 样本质量 |
| `data.coverage` | 参与指数、缺失指数、来源代码和覆盖率 |
| `meta.data_status` / `meta.warnings` | 状态和质量提示 |

### 6.2 上证综指基本面

固定证券代码为 `000001.SH`，调用：

```http
GET /api/v1/market-analysis/securities/000001.SH/fundamentals
```

接口请求必须按现有 Gateway 契约传递日期范围和分页参数；若后端支持指标/窗口参数，前端使用与综合区相同的指标和窗口。若该接口只返回分页历史基本面记录，则由前端 service 层将记录映射成日期序列；分位摘要必须使用接口已返回的分位字段或后续明确的后端结果，前端不得自行计算百分位。

上证区固定展示名称“上证综指”，并显示 `000001.SH`。不得使用综合接口的 `series`、综合分位或其他指数数据作为上证回退数据。

### 6.3 请求编排

- 页面首次打开时并行请求综合区和上证区；两个请求独立维护状态。
- 指标或窗口变化时，只刷新必要的数据请求；请求序号或 `AbortController` 防止旧响应覆盖新选择。
- service 层负责 URL、认证头、非 2xx 错误转换和 DTO 映射；组件不得直接调用 `fetch`。
- 两个接口应使用统一的 `IndexTrendQuery`、`IndexTrendSeries`、`IndexTrendSummary` 前端类型；上证接口字段差异在 service 层适配。
- 不在本地长期缓存历史结果；同一次打开期间可复用相同 query 的内存请求结果。

## 7. 状态和错误处理

| 状态 | 页面表现 |
| --- | --- |
| 初始加载 | 两个图表显示固定尺寸 skeleton，控制器可见但暂不可提交重复请求 |
| 单区加载中 | 对应趋势区显示 loading 遮罩，另一分区保持可用 |
| `VALID` / `COMPLETE` | 显示完整摘要、曲线和分位线 |
| `PARTIAL` | 显示可用曲线，并列出缺失指数或字段 warning |
| `INSUFFICIENT_DATA` | 显示曲线（如有）和“样本不足，暂不形成可靠分位” |
| `NO_DATA` | 固定图表容器显示“当前窗口暂无数据” |
| `UNAVAILABLE` | 显示依赖不可用说明，不显示伪造指标 |
| 请求失败 | 对应分区显示错误和“重试”按钮，不清空另一分区 |
| 权限失败 | 显示“暂无访问权限”，不循环重试 |

部分接口成功时，弹窗仍保持打开；成功区与失败区必须有明确标题，不能将一个区的数据状态扩散到另一个区。

```text

│   ├── IndexTrendToolbar.tsx

│   └── indexTrendApi.ts

```

- `TopBar` 只负责入口回调和 active 样式，不持有图表请求状态。
- `IndexTrendModal` 负责弹窗生命周期、焦点管理和整体布局。
- `useIndexTrend` 负责 query、并行请求、取消旧请求和局部状态。
- `IndexTrendChart` 只接收标准化序列和 summary，不包含业务计算。
- 图表库沿用项目已有依赖；不为本功能新增自绘 SVG 图表实现，除非现有图表能力无法满足 tooltip、缩放和参考线需求。

## 9. 验收标准

1. TopBar 的“指数趋势”位于“选股”右侧，桌面端可打开弹窗，关闭后回到原页面状态。
2. 弹窗默认请求综合 `PE`、`1Y` 和上证 `000001.SH` 基本面数据。
3. 综合区只调用 `/indices/composite/fundamentals`，不发送 `style`，并正确展示 `series`、`current`、`percentile`、`p10`、`p50`、`p90`。
4. 上证区只使用 `000001.SH` 的基本面响应，不把综合序列当作上证走势。
5. 切换 `PE/PETTM/PB` 和时间窗口后，请求参数和图表标题同步更新；综合接口的风格固定为 `overall`，当前不提供其他风格切换。
6. 前端不重新计算权重、共同日期、分位、参考线数值或估值价格。
7. `PARTIAL`、`INSUFFICIENT_DATA`、`NO_DATA`、权限失败和网络失败均有独立可识别的界面状态。
8. 一个接口失败不会清空另一接口已成功的数据；重试只作用于失败区。
9. 桌面端、平板端和手机端无横向页面溢出，图表和控制器文字不重叠。
10. 键盘可完成打开、关闭和控制器操作，关闭后焦点返回 TopBar 入口。

## 10. 待后端确认事项

- 上证基本面接口的正式响应 DTO 是否包含 `metric`、`window`、`summary` 或分位字段；若当前只返回历史记录，需要后端提供分位摘要接口或明确由 Gateway 聚合。
- 上证接口是否接受 `metric`、`window`；若不接受，前端需要分别按日期范围请求并在后端结果中获得对应指标的摘要。
- 综合接口当前 `style` 固定为 `overall`，因此本弹窗的“防御/平衡/进攻”控制器只能在后端提供对应接口后启用；在此之前应隐藏或置为不可用，而不是向综合接口发送未知参数。

- 设计截图中的“市场情绪”对照线不属于本次指定的两个接口；没有明确数据接口前不实现该线。
