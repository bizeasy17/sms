# 股票选股页面设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 页面名称 | 股票选股工作台 |
| 参考设计 | `docs/requirements/ui/stock-research-workspace_with_selection.html` |
| 前端项目 | `manniu/manniu_frontend` |
| 技术栈 | React、TypeScript、Vite |
| 页面入口 | 顶部导航“选股” |
| 页面定位 | 按交易范围、报告期和财务条件筛选股票，并查看、排序、导出结果 |
| 设计目标 | 筛选条件清晰、结果可扫描、状态可解释、桌面与移动端均可完成选股 |

选股页面服务于研究工作流中的候选发现阶段。用户进入页面后，应能完成以下任务：

1. 选择选股日期、报告年份、数据口径和股票范围。
2. 在传统估值、预测估值、财务表现之间切换筛选模式。
3. 配置行业、指标可用性、最小阈值和排序方向。
4. 查看筛选结果的关键指标，分页浏览并导出 CSV。
5. 从结果进入对应股票的研究详情页。

## 2. 设计原则

### 2.1 选股优先

- 选股页使用单一主工作区，不显示研究详情页的左侧股票覆盖池和右侧研究事件栏。
- 筛选区位于结果表上方，页面首屏优先保证条件可读和结果可见。
- 过滤条件使用明确的字段名、单位和报告口径，不依赖颜色解释业务含义。
- 查询条件变化后，结果区必须同步显示加载、空结果或错误状态。

### 2.2 克制的信息层级

- 页面背景使用低对比度冷灰色，筛选卡和结果区域使用白色。
- 研究蓝用于当前模式、选中条件、主操作和可点击股票代码。
- 青绿色表示正向或可用，琥珀色表示关注或低估排序，红色表示风险或错误。
- 卡片只用于筛选条件组和结果表容器，避免在卡片内继续嵌套装饰性卡片。
- 输入、分段控件和按钮使用不超过 `8px` 的轻量圆角。
- 数字、股票代码、日期和百分比使用等宽字体，保证表格列对齐。

### 2.3 条件可追溯

- 当前生效的所有条件都应能从控件状态读取，不通过隐含默认值改变查询含义。
- 切换选股模式时保留通用条件，并重置或隐藏不适用于当前模式的专属条件。
- 查询结果应回显实际使用的日期、报告期和排序条件，避免用户误读旧结果。
- URL 或页面状态应保存可分享的筛选条件；刷新页面后恢复相同查询。

## 4. 页面布局

### 4.1 桌面端（大于 1050px）

- 顶部导航固定，高度约 `56px`。
- 选股页面采用单列主工作区，不显示研究页的股票栏和事件栏。
- 主体最大宽度不强制限制为研究页宽度，允许结果表横向展示较多财务列。
- 页面左右内边距建议为 `34px`，筛选区和结果表上下间距约 `14px`。
- 筛选卡使用八列栅格：普通字段占一列，模式、范围、排序方向等长控件按需占两至四列。
- 结果表放在独立白色区域内；当列数超过视口宽度时，表格横向滚动，不压缩关键数字。

### 4.2 中等屏幕（701px 至 1050px）

- 保留单列选股工作区，减少页面左右内边距。
- 筛选栅格可从八列回落为四列，长控件占满两列或整行。
- 结果表继续保持最小宽度并允许横向滚动。
- 导出和排序按钮允许换行，但分页信息不能被按钮遮挡。

### 4.3 手机端（不大于 700px）

- 顶部只保留菜单入口、品牌标识、搜索入口和用户入口。
- 选股页不显示研究页股票抽屉；页面内容使用单列布局。
- 筛选卡内部字段改为单列或两列，阈值控件保持稳定高度。
- 分段控件在可用宽度不足时横向滚动或换行，不能让文字溢出按钮。
- 结果表保留横向滚动，表头与数据列必须保持同一滚动容器。
- 分页、导出和排序操作允许换行；结果总数和当前范围单独占一行。
- 搜索框在窄屏保留为紧凑入口；小于 `380px` 时只展示搜索图标区域。

## 5. 筛选区设计

### 5.1 基础条件

| 字段 | 控件 | 默认行为 | 规则 |
| --- | --- | --- | --- |
| 选股日期 | 日期输入框 | 使用当前可用交易日或后端提供的默认日期 | 不允许查询未来交易日；无交易数据时提示可用日期 |
| 财报所属年份 | 下拉框 | 当前年份或后端最新年份 | 选项由可用财务数据年份决定 |
| 时长 | 三段控件 | `60` | 可选 `30`、`60`、`200`，表示行情或观察窗口 |
| 选股模式 | 模式标签按钮 | 保持上次选择，首次进入使用财务表现 | 切换后刷新模式专属字段和结果列 |
| 报告口径 | 四段控件 | `H1` | 可选 `Q1`、`H1`、`Q3`、`FY` |
| 范围 | 六段控件 | 不筛选 | 可选自选、沪市、深市、创业板、科创板 |
| SW行业 | 下拉框 | 不筛选 | 支持行业名称，提交时使用稳定行业编码 |

控件状态要求：

- 选中态使用研究蓝背景和白色文字，同时保留可读的文本标签。
- 日期、年份、报告口径和范围变化后，结果区显示新的查询状态，不展示旧数据为最新结果。
- 下拉选项为空时显示“暂无可选项”，不能渲染空白下拉框。
- 所有输入控件必须支持键盘操作，并有可关联的 `label` 或等效无障碍名称。

### 5.2 财务表现模式字段

财务表现模式使用以下筛选字段。百分比阈值统一以百分数展示，例如输入 `3` 表示 `3%`；前端提交时遵循现有接口的数据单位约定，不在展示层静默改变用户输入。

| 字段 | 类型 | 默认值 | 展示单位 |
| --- | --- | --- | --- |
| 全部指标可用 | 开关 | 开启 | 无 |
| 排序条件 | 下拉框 | 财务表现分 | 无 |
| 营收同比最小值 | 步进输入 | `3` | `%` |
| 营收环比最小值 | 步进输入 | `3` | `%` |
| 净利同比最小值 | 步进输入 | `3` | `%` |
| 净利环比最小值 | 步进输入 | `3` | `%` |
| EBIT 同比最小值 | 步进输入 | `3` | `%` |
| EBIT 环比最小值 | 步进输入 | `3` | `%` |
| ROE 最小值 | 步进输入 | `3` | `%` |
| 扣非 ROE 最小值 | 步进输入 | `3` | `%` |
| 排序方向 | 二段控件 | 从高到低 | 无 |

交互规则：

- 步进输入提供减号、数值输入和加号三个稳定区域。
- 最小值必须是合法数字；非法值不能触发请求，并在字段附近提示原因。
- “全部指标可用”开启时，仅返回所有必要指标齐全的股票；关闭时允许部分指标缺失，但缺失值必须在结果中明确展示。
- 输入条件修改后采用显式查询提交，或使用防抖查询，但必须避免每次按键都触发并发请求。
- 切换排序条件或方向时，分页回到第一页。

### 5.3 其他模式

传统估值和预测估值模式沿用同一筛选卡布局，模式专属条件由配置驱动。前端要求：

- 通用字段位置保持稳定，减少模式切换后的认知成本。
- 模式专属字段必须有明确标题和单位。
- 未实现或暂不可用的模式应显示禁用态和原因，不允许点击后出现空白结果。
- 结果表列根据模式切换，但代码、行业、报告期和公告日等基础列保持一致。

## 6. 结果表设计

### 6.1 财务表现模式默认列

结果表按以下顺序展示：

1. 股票代码。
2. SW 行业。
3. 财报期。
4. 公告日。
5. 营收 YoY（%）。
6. 营收 QoQ（%）。
7. 净利 YoY（%）。
8. 净利 QoQ（%）。
9. EBIT YoY（%）。
10. EBIT QoQ（%）。
11. ROE（%）。
12. 扣非 ROE（%）。
13. 财务分。
14. 传统估值价。

表格规则：

- 股票代码是进入研究详情页的链接，点击后保留当前选股条件。
- 数值列右对齐或使用等宽字体；百分比和价格必须带单位或通过表头明确单位。
- 缺失数据显示 `--` 或“缺失”，不显示 `0` 伪装成有效指标。
- 正负变化值可使用颜色辅助，但不能只用颜色区分正负。
- 表头保持单行优先；列宽不足时使用横向滚动，不截断关键值。
- 支持表头排序时，排序方向、当前列和请求状态应有清晰反馈。
- 结果行可点击进入研究页，但点击单元格链接和点击整行不能产生两次导航。

### 6.2 空、加载和错误状态

| 状态 | 表现 | 操作 |
| --- | --- | --- |
| 首次加载 | 保留表头并显示行级骨架 | 不显示旧结果 |
| 查询中 | 表格保留上一页结构，显示轻量加载提示 | 禁止重复提交 |
| 无结果 | 表体显示“暂无符合条件的股票”及当前条件摘要 | 提供清空条件或调整阈值 |
| 请求失败 | 表格区域显示错误原因和重试按钮 | 保留用户已填写的筛选条件 |
| 部分字段缺失 | 行可展示，缺失单元格显示 `--` | 开启“全部指标可用”时按规则过滤 |
| 导出失败 | 保留当前页面，提示导出失败原因 | 可再次导出 |

“No Data”只适合作为接口尚未提供结果时的技术占位，不作为最终面向用户的空状态文案。

## 7. 分页、导出和快捷排序

### 7.1 分页

- 默认展示第一页结果，分页大小由现有接口或项目统一配置决定。
- 上一页在第一页禁用，下一页在最后一页或没有下一页时禁用。
- 分页切换只改变页码，不丢失其他筛选条件。
- 分页信息展示“命中总数”和“当前范围”，例如“命中总数：120｜当前范围：1-20”。
- 新查询、切换模式、切换报告口径或排序条件后回到第一页。

### 7.2 CSV 导出

- 导出使用当前全部筛选条件和排序条件，不只导出当前页，除非产品明确提供“导出当前页”选项。
- 导出按钮在无结果、查询中和无权限时禁用，并给出原因。
- 导出文件应包含表头、查询日期、报告口径和实际筛选条件摘要。
- 导出过程中显示进行中状态，防止重复下载。
- 文件名建议包含模式、选股日期和报告口径，例如 `stock_picker_financial_20260911_H1.csv`。

### 7.3 低估分快捷排序

页面底部可提供“低估分排序”和“低估分升序”快捷操作。它们本质上是预设排序条件：

- 点击后更新排序条件和方向，并回到第一页。
- 快捷操作的选中状态必须与筛选区中的排序条件保持一致。
- 当前模式不支持低估分时，按钮禁用并显示不可用原因。

## 8. 前端组件与状态边界

建议组件拆分如下：

- `AppShell`：页头、全局导航、用户菜单和路由容器。
- `StockPickerPage`：页面级查询状态、数据请求和错误边界。
- `PickerFilterCard`：筛选条件布局和条件校验。
- `ModeSelector`：传统估值、预测估值、财务表现切换。
- `ReportPeriodSelector`：报告口径、年份和日期条件。
- `ScopeSelector`：自选、市场和板块范围选择。
- `NumericStepper`：财务阈值输入及键盘交互。
- `PickerResultTable`：表头、数据行、缺失值和行导航。
- `PickerStateView`：加载、空结果和错误状态。
- `PaginationBar`：分页、总数和当前范围。
- `ExportButton`：导出状态、防重复点击和失败提示。

页面级状态至少包括：

```ts
type PickerQuery = {
  tradeDate: string;
  fiscalYear: number;
  duration: 30 | 60 | 200;
  mode: 'traditional' | 'predictive' | 'financial';
  reportType: 'Q1' | 'H1' | 'Q3' | 'FY';
  scope: 'all' | 'watchlist' | 'sh' | 'sz' | 'chinext' | 'star';
  swIndustry?: string;
  allMetricsAvailable: boolean;
  sortBy: string;
  sortDirection: 'asc' | 'desc';
  thresholds: Record<string, number | null>;
  page: number;
  pageSize: number;
};
```

实现约束：

- 查询参数、结果数据和展示格式化分离，表格组件不直接拼接请求参数。
- 使用请求标识或取消机制，避免旧请求覆盖新筛选结果。
- 结果数据为空时保留筛选状态和表头，不能卸载整个页面导致输入丢失。
- 股票代码进入研究详情页时，将 `PickerQuery` 序列化到路由或可恢复状态中。
- 后端返回的比例字段必须依据接口契约统一格式化；前端不得对同一字段在不同列重复换算。

## 9. 无障碍与可用性

- 所有控件拥有可读标签；步进按钮使用“增加/减少 + 字段名”的完整 `aria-label`。
- 分段按钮使用 `aria-pressed` 或等效语义表达选中状态。
- 开关使用 `role="switch"` 和同步的 `aria-checked`。
- 表格使用真实 `table` 结构，表头与数据单元格保持可关联关系。
- 加载、查询失败和导出结果使用 `aria-live` 提示，但不频繁播报每次输入变化。
- 颜色只作为辅助信息，状态必须同时包含文字、图标或数值方向。
- 键盘可以完成模式切换、条件修改、分页、导出和进入股票详情。

## 10. 验收标准

### 功能验收

- 能选择日期、年份、时长、模式、报告口径、股票范围和行业。
- 财务表现模式的八个阈值可独立修改，并能正确提交。
- “全部指标可用”开关能影响结果过滤逻辑。
- 排序条件、排序方向和低估快捷排序能同步更新结果。
- 查询结果支持分页、股票详情跳转和 CSV 导出。
- 查询失败、无结果、字段缺失和导出失败都有明确状态。

### 视觉验收

- 桌面端筛选区、结果表和分页区层级清晰，控件不重叠。
- 表格列过多时横向滚动，页面不出现整体横向溢出。
- 手机端筛选控件、表格和操作按钮可操作，文字不被截断或遮挡。
- 当前选中态、禁用态、加载态和错误态均不只依赖颜色。
- 页面视觉语言与研究工作台一致：冷灰背景、白色内容区、研究蓝主色、低饱和状态色。

### 性能验收

- 输入条件快速变化时不会产生无法控制的并发请求。
- 分页和排序切换不重复加载全局资源。
- 大结果集使用服务端分页；前端不一次性渲染全部数据。
- 导出任务不会阻塞结果表交互，并能显示明确的进行中状态。
