# 股票选股页面前台设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 页面名称 | 财务表现选股工作台 |
| 参考截面 | `docs/requirements/ui/financial-performance-screener.html` |
| 前端项目 | `manniu/manniu_frontend` |
| 技术栈 | React、TypeScript、Vite |
| 页面入口 | 顶部导航“选股” |
| 页面路径 | `/stock-picker` |
| 页面定位 | 通过盈利质量、成长性、估值与风险条件筛选候选股票 |
| 当前阶段 | SW 行业目录和选股结果均已接入服务端；结果页使用真实查询返回值 |

本页面服务于研究工作流中的候选发现阶段。用户应能在同一工作区完成筛选条件配置、查看结果摘要、扫描财务指标，并进入个股研究档案。

## 2. 设计基准

页面视觉和布局以 `financial-performance-screener.html` 为基准，不再采用“筛选条件全部堆叠在结果表上方”的布局。

- 顶部为固定全局导航，高度约 `56px`。
- 主体为两栏布局：左侧筛选器，右侧结果工作区。
- 左侧筛选器桌面端固定在顶部导航下方，独立滚动。
- 右侧工作区展示面包屑、页面标题、更新结果按钮、摘要指标和结果表。
- 使用冷灰背景、白色内容面、研究蓝主色、青绿色正向状态、琥珀色关注状态和红色风险状态。
- 数字、股票代码、日期、百分比和评分使用等宽字体；公司名称和行业使用中文无衬线字体。
- 控件和容器使用 `4px` 至 `6px` 轻量圆角，避免装饰性大卡片和渐变背景。

## 4. 页面布局

### 4.1 桌面端（大于 780px）

- 顶栏固定在视口顶部，内容高度约 `56px`。
- 主体从顶栏下方开始，采用 `280px + minmax(0, 1fr)` 两列布局。
- 左侧筛选器宽度约 `280px`，高度为视口剩余高度，内容超出时独立滚动。
- 右侧主区域最大宽度约 `1400px`，左右内边距约 `36px`，底部内边距约 `60px`。
- 右侧标题区底部使用细分隔线；“更新结果”位于标题区右侧。
- 摘要指标使用三列等宽布局，指标之间使用细线分隔。
- 结果表使用白色边框容器；列数较多时只允许表格容器横向滚动，页面整体不横向溢出。

### 4.2 手机端（不大于 780px）

- 顶栏高度约 `52px`，显示菜单按钮、品牌标记、紧凑搜索入口；隐藏完整导航和用户头像。
- 左侧筛选器变为固定抽屉，默认从左侧移出；点击顶栏菜单按钮打开。
- 主区域改为单列，内边距约 `16px`。
- 标题和“更新结果”允许并排但不得互相挤压；说明文字可换行。
- 摘要指标使用两列布局，第三项占满整行。
- 结果表保留最小宽度并在独立容器内横向滚动。
- 移动端隐藏结果视图切换按钮，优先保证筛选和表格可读性。

## 5. 顶部导航

| 元素 | 桌面端 | 移动端 | 行为 |
| --- | --- | --- | --- |
| 菜单按钮 | 隐藏 | 显示 | 打开或关闭筛选器抽屉 |
| 品牌 | 显示品牌标记和名称 | 仅显示品牌标记 | 点击返回研究页 |
| 研究 | 显示 | 隐藏 | 跳转 `/`，取消选股选中态 |
| 选股 | 显示且为当前选中态 | 隐藏 | 跳转 `/stock-picker` |
| 公司搜索 | 宽度约 `255px` | 占用剩余空间 | 复用现有公司搜索能力 |
| 用户入口 | 显示头像或用户菜单 | 隐藏 | 复用现有账号状态 |

选股页面加载时，“选股”必须使用 `active` 状态，“研究”不得保持选中。导航链接必须直接使用 `/stock-picker`，不能使用 `#universe` 作为最终入口。

## 6. 左侧筛选器

### 6.1 筛选器头部

- 顶部显示小号字母间距标题“筛选器”。
- 首次进入页面显示一个“优质盈利增长”保存方案提示区域。
- 保存方案提示包括方案名称和一句简短说明，例如“高 ROE、收入与利润增长，同时控制估值与负债风险”。
- 当前阶段保存方案可以是静态展示；接入接口后再支持保存、覆盖和删除。

### 6.2 盈利质量

使用开关型条件，每行左侧为条件名称，右侧为开关：

| 条件 | 默认值 |
| --- | --- |
| ROE ≥ 10% | 开启 |
| 毛利率同比改善 | 开启 |
| 经营现金流为正 | 开启 |

开关必须使用 `role="switch"` 和 `aria-checked`。开启使用青绿色，关闭使用浅灰色，不能仅依赖颜色传达状态。

### 6.3 成长性

使用范围滑块或等效数值范围控件：

| 条件 | 默认值 | 范围 |
| --- | --- | --- |
| 营收增速 | ≥ 10% | `0%` 至 `30%` |
| 净利润增速 | ≥ 10% | `0%` 至 `30%` |

每个范围控件必须显示当前阈值和范围端点。若项目暂不使用双端滑块，单阈值滑块也必须提供可键盘调整的数字输入或步进按钮。

### 6.4 估值与风险

| 条件 | 控件 | 默认值 |
| --- | --- | --- |
| PE 分位低于 | 范围滑块或数值输入 | `70%` |
| 资产负债率 | 开关或阈值控件 | `≤ 60%`，开启 |

### 6.5 数据范围

| 字段 | 控件 | 默认值 |
| --- | --- | --- |
| 报告期 | 下拉或只读选择器 | `2026 H1` |
| 市场 | 下拉或只读选择器 | `沪深 A 股` |
| 选股日期 | 日期选择器 | 当前可用交易日 |
| SW 行业 | 下拉选择器 | 全部行业；从 `/api/v1/market-analysis/sw-industries?level=L3` 加载 |

未来日期不能提交。年份、报告期、市场和行业选项为空时显示“暂无可选项”，不能显示空白控件。SW 行业列表必须调用 `/api/v1/market-analysis/sw-industries` 并固定传递 `level=L3`，使用 `industry_code` 作为选项值、`name` 作为显示文本；请求期间显示“正在加载行业...”，接口失败显示“行业列表加载失败”及错误提示，不得回退到静态行业列表。

## 7. 主区域

### 7.1 面包屑和标题

面包屑使用：

```text
发现 / 因子筛选 / 财务表现
```

页面标题为“财务表现选股”，说明文字为：

```text
从盈利质量、成长性与财务安全性中筛出值得深入研究的公司。
```

“更新结果”按钮是主操作。侧栏和标题区的两个按钮共用同一个提交处理器，提交当前筛选条件到 `GET /api/v1/market-analysis/stock-selection/results`，不能在每次输入时发起请求。请求进行中时两个按钮均禁用并显示“更新中...”。请求成功后，服务端返回的当前页结果替换演示行；请求失败时保留当前结果并显示错误提示。

### 7.2 结果摘要

摘要区域展示三个指标：

| 指标 | 示例 | 说明 |
| --- | --- | --- |
| 符合条件 | `matched_count` | 当前筛选命中的股票数 |
| 覆盖公司 | `market_stock_count` | 当前市场和报告期范围内的公司数 |
| 最近更新 | 当前查询日期 | 当前请求使用的 `asof_date` |

摘要指标必须回显当前实际查询状态，不能在查询中继续展示上一组条件的数字作为最新结果。首次加载、加载中、失败和无结果都需要有对应状态；结果表缺失字段显示 `--`，不能把空值转换为 `0`。

### 7.3 结果工具栏

左侧显示“筛选结果”和当前排序说明，例如“按综合财务评分排序”。右侧提供视图切换：

- 财务表现：默认选中。
- 估值：预留给估值结果视图。
- 技术面：预留给技术指标视图。

未实现视图可以显示禁用态和原因，不允许点击后出现空白区域。财务表现视图必须优先完成。

## 8. 财务表现结果表

### 8.1 列顺序

| 顺序 | 列 | 展示规则 |
| --- | --- | --- |
| 1 | 公司 | 公司名称为链接，下方显示 `ts_code` |
| 2 | 所属行业 | 显示 SW 行业名称 |
| 3 | 财务评分 | 评分徽标，支持普通和关注两级样式 |
| 4 | 营收增速 | 百分比，正向值带 `+` |
| 5 | 净利润增速 | 百分比，正向值带 `+` |
| 6 | ROE | 百分比 |
| 7 | 毛利率变化 | 使用 `pct` 单位，例如 `+2.1pct` |
| 8 | 经营现金流 | 百分比或接口约定单位 |
| 9 | PE 分位 | 百分比 |

### 8.2 表格规则

- 使用真实 `table`、`thead`、`tbody` 结构。
- 公司名称链接进入研究详情页，并保留当前筛选条件及排序条件。
- 股票代码、日期、百分比、评分和金额使用等宽字体，数字列右对齐。
- 正向、风险和关注状态同时使用符号、文字或数值方向，不能只依赖颜色。
- 缺失值显示 `--` 或“缺失”，不能用 `0` 代替。
- 表头保持单行优先；窄屏通过表格容器横向滚动。
- 表格行可以支持点击进入详情，但点击公司链接不能触发两次导航。
- 服务端分页时前端只渲染当前页，不一次性渲染完整结果集。

## 9. 状态与交互

### 9.1 查询状态

| 状态 | 页面表现 | 可用操作 |
| --- | --- | --- |
| 首次加载 | 保留表头和行级骨架 | 不显示过期结果 |
| 查询中 | 表格结构保留，显示轻量加载提示 | 禁止重复提交 |
| 有结果 | 显示摘要、结果表和说明 | 分页、排序、进入研究页 |
| 无结果 | 显示“暂无符合条件的股票”和条件摘要 | 调整条件、清空条件 |
| 请求失败 | 显示具体错误和重试按钮 | 保留已填写条件 |
| 字段缺失 | 单元格显示 `--` | 允许进入详情或调整“全部指标可用” |

### 9.2 条件提交

- 输入条件变更只更新草稿状态，不立即刷新结果。
- 点击“更新结果”后生成查询快照，重置分页到第一页。
- 查询结果必须显示实际报告期、市场、更新时间和排序条件。
- 使用请求标识或取消机制，禁止旧请求覆盖新查询结果。
- 过滤条件、结果数据和格式化逻辑分离，表格组件不拼接请求参数。

### 9.3 排序与分页

- 默认按综合财务评分降序。
- 支持按财务评分、营收增速、净利润增速、ROE 和 PE 分位排序。
- 切换排序字段或方向后回到第一页，并在工具栏显示当前排序。
- 分页信息展示“命中总数”和当前范围，例如“命中总数：86｜当前范围：1-20”。
- 上一页在第一页禁用，下一页在最后一页禁用。

### 9.4 导出

- 结果工具栏或分页区提供“导出 CSV”。
- 导出使用最近一次已提交的完整筛选条件和排序条件，而不是草稿条件。
- 无结果、查询中、无权限时按钮禁用并说明原因。
- 导出中防止重复点击，并使用 `aria-live` 提示完成或失败。
- 文件名建议为 `stock_picker_financial_YYYYMMDD_reportType.csv`。

## 10. 页面状态模型

```ts
type PickerQuery = {
  tradeDate: string;
  fiscalYear: number;
  reportType: 'Q1' | 'H1' | 'Q3' | 'FY';
  market: 'all' | 'sh' | 'sz' | 'chinext' | 'star';
  swIndustry?: string;
  profitability: {
    roeMin: number | null;
    grossMarginImproved: boolean;
    operatingCashFlowPositive: boolean;
  };
  growth: {
    revenueYoyMin: number | null;
    netProfitYoyMin: number | null;
  };
  valuationRisk: {
    pePercentileMax: number | null;
    debtToAssetsMax: number | null;
  };
  sortBy: 'financialScore' | 'revenueYoy' | 'netProfitYoy' | 'roe' | 'pePercentile';
  sortDirection: 'asc' | 'desc';
  page: number;
  pageSize: number;
};

type PickerViewState =
  | { status: 'idle' }
  | { status: 'loading'; query: PickerQuery }
  | { status: 'ready'; query: PickerQuery; total: number; rows: PickerRow[] }
  | { status: 'empty'; query: PickerQuery }
  | { status: 'error'; query: PickerQuery; message: string };
```

草稿筛选条件和最近一次已提交查询必须分开保存，避免用户修改输入时结果表被误认为已经更新。可分享的查询条件应序列化到 URL；进入个股研究页时保留该查询快照。

## 11. 组件边界

- `AppShell`：固定顶栏、品牌、全局导航、搜索和用户入口。
- `StockPickerPage`：页面状态、查询提交、请求取消和错误边界。
- `FilterSidebar`：桌面筛选器和移动端抽屉容器。
- `SavedScreenCard`：保存方案提示或保存方案入口。
- `FilterGroup`：盈利质量、成长性、估值风险和数据范围分组。
- `ToggleField`：带无障碍语义的开关字段。
- `ThresholdRangeField`：滑块、数值输入和范围端点。
- `ResultSummary`：符合条件、覆盖公司、最近更新。
- `ResultToolbar`：结果标题、排序说明和视图切换。
- `FinancialResultTable`：表头、行、缺失值、公司链接和排序状态。
- `PickerStateView`：加载、空结果和错误状态。
- `PaginationBar`：分页、结果范围和导出。

## 12. 无障碍要求

- 每个筛选控件都有可见标签或关联的 `label`。
- 开关使用 `role="switch"`、同步 `aria-checked`，并提供完整字段名称的 `aria-label`。
- 滑块使用 `role="slider"` 或原生 range，并设置 `aria-valuemin`、`aria-valuemax`、`aria-valuenow`。
- 顶栏菜单按钮、关闭筛选抽屉按钮和导出按钮拥有明确的 `aria-label`。
- 表格使用真实表头，必要时通过 `scope="col"` 关联列。
- 查询中、错误、导出完成和导出失败使用 `aria-live`，不播报每次输入变化。
- 键盘可以完成打开筛选器、修改条件、提交查询、排序、分页、导出和进入股票详情。
- 颜色只作为辅助信息，正负方向和异常状态必须同时有符号、文字或数值表达。

## 13. 验收标准

### 功能验收

- 选股菜单直接进入 `/stock-picker`，进入页面后选股导航为选中态。
- 桌面端显示左侧固定筛选器和右侧结果工作区，移动端筛选器可抽屉打开。
- 盈利质量三个开关、成长性两个阈值、PE 分位和资产负债率条件可修改。
- 报告期、市场、日期和 SW 行业可选择，并显示当前实际条件。
- 点击“更新结果”才提交查询，查询期间不能重复提交。
- 摘要正确展示命中数、覆盖公司和最近更新状态。
- 结果表按财务表现截面展示九列核心指标，缺失值显示 `--`。
- 支持排序、服务端分页、CSV 导出和股票详情跳转。
- 无结果、加载失败、字段缺失和导出失败均有明确状态和恢复操作。

### 视觉验收

- 页面整体符合参考截面的“固定顶栏 + 左筛选器 + 右结果区”结构。
- 左侧筛选器不随右侧结果滚动，超出视口时自身滚动。
- 摘要指标、结果表和筛选分组层级清晰，控件没有重叠。
- 表格列过多时只有表格容器横向滚动，页面不出现整体横向溢出。
- 手机端筛选抽屉、标题、摘要、表格和操作按钮均可操作，文字不被截断。
- 选中态、禁用态、加载态和错误态不只依赖颜色。

### 性能验收

- 快速修改多个条件不会产生不可控的并发请求。
- 分页、排序和查询不会重复加载全局资源。
- 大结果集使用服务端分页，前端不一次性渲染所有行。
- 导出过程不会阻塞结果表和筛选器的其他交互。
