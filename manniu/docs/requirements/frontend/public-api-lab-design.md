# 公共 API Lab 前端设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 页面名称 | 公共 API Lab / 接口浏览测试 |
| 页面入口 | `/public/api` |
| 前端项目 | `manniu/manniu_frontend` |
| 主要实现 | `manniu_frontend/src/App.tsx`、`manniu_frontend/src/ApiLab.tsx` |
| 技术栈 | React、TypeScript、Vite |
| 页面定位 | 面向已登录用户的只读接口目录浏览、参数填写和请求验证工作台 |

API Lab 不是业务数据展示页，也不是对外开放的 API 文档站。它使用当前账号的访问权限，让开发、测试和内部运营人员快速确认：

1. 当前账号可以访问哪些公共只读接口。
2. 接口需要哪些路径参数和查询参数。
3. 请求的 HTTP 状态、响应体、耗时和请求追踪 ID。

## 2. 设计目标与边界

### 2.1 目标

- 用接口目录替代手工记忆路径，目录分组和搜索结果必须可扫描。
- 参数表单由后端目录元数据驱动，展示参数位置、类型、必填状态、默认值或示例值。
- 请求发送前校验必填参数，发送后同时展示业务响应和网络元信息。
- 登录失效时清理本地凭证并引导用户重新登录。
- 在桌面和小屏幕上都能完成“选择接口 -> 填参 -> 发送 -> 查看响应”的闭环。

### 2.2 非目标

- 不在前端执行写入、删除、批量操作或自动交易。
- 不允许用户在页面中自定义任意 URL、HTTP 方法或请求头。
- 不把 API Lab 变成完整的 OpenAPI 编辑器、SDK 生成器或业务操作后台。
- 不在响应区展示、复制或持久化密码、刷新令牌等敏感凭证。

## 4. 访问与认证流程

### 4.1 未登录访问

- 访问 `/public/api` 时读取 `localStorage` 中的 `access_token`，兼容历史键 `auth_access_token`。
- 没有有效令牌时只显示认证提示、`/login` 入口和返回研究工作台入口，不加载接口目录。
- 登录页调用 `${VITE_API_BASE_URL ?? '/api/v1'}/auth/login`，请求体包含 `username`、`password` 和 `client_type: "WEB"`。
- 登录成功后保存 `access_token`；若响应提供 `refresh_token`，保存刷新令牌，并跳转回 `/public/api`。
- 登录失败显示后端错误消息或通用失败提示，不回显密码。

### 4.2 已登录访问

- 页面加载后调用 `GET /public-api/catalog`，请求头携带 `Authorization: Bearer <access_token>`。
- 目录加载成功后默认选中第一个分组中的第一个接口。
- 目录返回 `401` 时清除访问令牌，停止使用旧目录，并提示“登录凭证已过期，请重新登录”。
- 退出操作清除访问令牌和兼容键；刷新页面后必须回到认证状态。
- 访问令牌只保存在既有认证机制使用的本地存储位置，不写入 URL、日志、响应展示区或文档示例。

## 5. 目录数据契约

目录由后端返回，前端只负责校验可展示结构和渲染，不自行推导可访问接口。建议契约如下：

```ts
type Parameter = {
  name: string
  in: 'path' | 'query' | 'header'
  type?: string
  required?: boolean
  default?: string | number | boolean
  example?: string | number | boolean
  enum?: string[]
}

type Endpoint = {
  id: string
  method: string
  path: string
  name: string
  description: string
  parameters: Parameter[]
}

type Catalog = {
  catalog_version?: string
  groups: {
    key: string
    name: string
    endpoints: Endpoint[]
  }[]
}
```

目录应只暴露允许公共测试的接口。前端默认只提供 `GET` 和 `HEAD` 方法筛选；即使后端目录误返回其他方法，也不得通过页面构造写请求。

## 6. 目录区设计

### 6.1 搜索和筛选

- 搜索匹配接口名称、路径和描述，忽略大小写并去除首尾空格。
- 领域筛选默认“所有领域”，选项使用目录分组的 `key` 和 `name`。
- 方法筛选默认“所有方法”，当前支持 `GET` 和 `HEAD`。
- 搜索、领域和方法筛选只影响目录可见项，不清空已选接口的请求结果，直到用户选择新的接口。
- 没有匹配项时显示“没有匹配的接口”，不能展示空白面板。
- 接口列表项至少展示方法、接口名称和路径；当前项必须有明确选中态，不能只依赖颜色。

### 6.2 目录状态

| 状态 | 展示 | 行为 |
| --- | --- | --- |
| 加载中 | 目录加载提示 | 禁止发送请求 |
| 加载成功 | 目录版本、接口数量和分组列表 | 默认选中第一个接口 |
| 无接口 | 空状态和返回入口 | 不渲染无意义的参数面板 |
| 加载失败 | 错误原因和重试入口 | 保留认证状态，不伪造目录 |
| 认证失效 | 登录凭证过期提示 | 清理令牌并引导登录 |

## 7. 详情与参数表单

### 7.1 接口详情

详情区按以下顺序展示：

1. 接口名称。
2. HTTP 方法和完整路径。
3. 接口描述。
4. 参数表单。
5. 发送请求操作。
6. 上一次响应及请求元信息。

切换接口时，按该接口的参数元数据初始化表单值：优先使用 `default`，其次使用 `example`，否则为空。切换接口应清空旧响应、状态码、耗时和请求 ID，避免用户把旧结果误认为新接口结果。

### 7.2 参数规则

- `path` 参数替换路径中的 `:name` 占位符，并使用 `encodeURIComponent` 编码。
- `query` 参数只在有值时加入查询字符串；空值不应被转换成无意义的空参数。
- `header` 参数不由普通用户表单提交，认证头由页面统一生成；禁止用户覆盖 `Authorization`。
- 必填参数在发送前校验。缺少参数时在响应区域显示明确的字段名，并且不发起网络请求。
- `enum` 参数应优先渲染为下拉选择；没有 `enum` 时按类型渲染文本、数字或布尔控件。
- 每个控件必须有可关联的标签、稳定的名称和键盘可操作状态。
- 参数的展示单位和示例应来自目录或接口约定，前端不得静默改变业务数值单位。

### 7.3 请求按钮

- 请求发送期间显示进行中状态，禁止重复点击。
- 请求必须携带 `Authorization: Bearer <access_token>`。
- 每次请求生成唯一 `X-Request-ID`；响应有同名响应头时优先展示服务端返回值，否则展示客户端生成值。
- 页面只根据已选目录接口拼接 URL，不接受用户输入的任意主机名或路径。
- 请求失败时区分网络失败和 HTTP 错误；不把网络异常伪装成成功响应。

## 8. 响应检查器

响应区需要同时展示：

- HTTP 状态码。
- 请求耗时，单位为毫秒。
- 请求追踪 ID。
- 格式化后的 JSON 响应体。

响应体规则：

- 对合法 JSON 使用两格缩进格式化，保持长文本可滚动，不撑破页面布局。
- 对空响应、非 JSON 响应或解析失败，显示可读的原始文本或通用错误提示。
- 状态码使用文本和颜色双重表达，例如“200 成功”“401 未授权”“500 服务异常”。
- 不在响应检查器中显示完整 `Authorization`、密码或刷新令牌；如后端误返回敏感字段，前端应在展示层脱敏并记录为安全缺陷。
- 保留最近一次结果，直到用户切换接口或重新发送请求；查询中可以保留旧结果，但必须显示正在请求状态。

## 9. 响应与异常状态

| 场景 | 用户可见行为 |
| --- | --- |
| 目录请求 `401` | 清除令牌，显示重新登录提示 |
| 接口请求 `401` | 提示凭证已失效，提供重新登录动作 |
| 接口请求 `403` | 显示当前账号无权限，不重试无效请求 |
| 接口请求 `404` | 显示接口不存在或目录已过期，提供重新加载目录 |
| 接口请求 `429` | 显示请求过于频繁，保留参数，不自动循环重试 |
| 接口请求 `5xx` | 显示服务端错误和请求 ID，允许手动重试 |
| 网络异常 | 显示服务不可达提示、耗时和请求 ID |
| 缺少必填参数 | 在请求前提示具体参数，不产生网络请求 |
| 无响应内容 | 显示状态码和“接口未返回内容”，不渲染空白成功态 |

## 10. 响应式布局

### 10.1 桌面端（大于 1050px）

- 页面顶部使用固定高度的工具栏。
- 工作区采用左右两栏：左侧目录约 `320px`，右侧详情自适应。
- 目录独立纵向滚动，详情区保持参数和响应的阅读宽度。
- 响应 JSON 使用等宽字体和内部滚动，不让长行撑宽整个页面。

### 10.2 中等屏幕（701px 至 1050px）

- 左侧目录缩小到约 `260px`，详情区保留最小可读宽度。
- 参数字段可从双列回落为单列。
- 目录筛选控件允许换行，但搜索框和接口方法标签不能重叠。

### 10.3 手机端（不大于 700px）

- 目录和详情改为纵向布局，目录位于详情上方。
- 目录高度受限并独立滚动，避免接口列表挤压响应区。
- 参数表单单列展示；按钮保持稳定高度并占满可用宽度。
- 方法、路径和接口名称允许换行，不能被截断到无法识别。
- JSON 响应横向滚动，不能通过缩小字体破坏代码可读性。
- 认证提示和错误信息必须在首屏可见，不能依赖悬浮提示传达关键状态。

## 11. 可访问性与视觉规范

- 选中接口、当前筛选和状态码均使用文本、结构和颜色共同表达。
- 搜索框、筛选框、参数控件和按钮都提供可访问名称。
- 键盘可以完成目录筛选、接口切换、参数填写和发送请求。
- 焦点状态清晰可见，不能只使用颜色区分焦点。
- 代码、路径、方法、状态码、耗时和请求 ID 使用等宽字体。
- 错误消息靠近相关区域显示，并保持足够对比度。
- 视觉风格与 ManNiuNiu 研究工作台一致：冷灰背景、白色工作区、研究蓝主操作、轻量边框和不超过 `8px` 的圆角。

## 12. 前端状态边界

建议将状态分为以下几类，避免请求逻辑和展示组件互相耦合：

- `authState`：当前访问令牌是否存在、是否失效。
- `catalogState`：目录数据、版本、加载状态和错误信息。
- `selectionState`：当前接口、搜索词、领域筛选和方法筛选。
- `requestFormState`：当前接口参数值和本地校验错误。
- `responseState`：响应体、状态码、耗时、请求 ID、加载状态和错误类型。

目录请求、接口请求和认证失效应共享统一的错误映射，但不应互相覆盖状态。例如接口请求失败不能清空目录，切换搜索条件也不能隐式重新发送请求。

## 13. 验收标准

- 未登录访问 `/public/api` 时不会请求接口目录，并能进入 `/login`。
- 登录成功后能加载目录，显示目录版本、分组和接口数量。
- 搜索、领域筛选和方法筛选能组合生效；无结果时有明确空状态。
- 选择接口后，参数默认值或示例值正确回填；缺少必填参数时不会发请求。
- 路径参数正确编码，查询参数只提交有值字段。
- 请求携带 Bearer 令牌和唯一 `X-Request-ID`，并展示状态码、耗时、响应体和请求 ID。
- `401`、`403`、`404`、`429`、`5xx`、网络异常和空响应均有可识别的状态反馈。
- 切换接口会清理旧响应，目录筛选不会误发请求。
- 桌面和手机端均无文本、按钮、参数控件或 JSON 响应重叠。
- 页面不提供任意 URL、写操作或自动交易入口。

## 14. 后续演进

以下能力应在接口契约和权限确认后再实现：

- OpenAPI 风格的 schema 展示和响应字段折叠。
- 请求历史和复制请求示例，但必须默认脱敏且不保存访问令牌。
- 目录缓存与版本变更提示。
- 按账号权限隐藏不可访问接口，而不是让用户反复收到 `403`。
- 只读响应中的字段搜索、路径复制和下载功能。
