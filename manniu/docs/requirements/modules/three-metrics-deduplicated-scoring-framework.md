# 三类指标去重后的评分框架

## 1. 文档目标

本框架用于重新定义并区分以下三类评分：

1. **财务健康度（FHS）**：公司当前经营基础是否健康。
2. **模型信号解释（MSI）**：模型为什么看好或看弱，主要依赖哪些特征。
3. **企业增长潜力（CGPS）**：公司是否正在出现可持续的经营改善。

框架的核心目标是避免三个评分体系反复使用相同指标、重复表达相同经济含义，并防止多个相似综合分给用户造成解释混乱。

---

## 2. 总体定位

| 评分体系 | 核心问题 | 时间属性 | 主要数据 | 是否包含估值 | 核心输出 |
|---|---|---|---|---|---|
| 财务健康度 FHS | 公司当前经营基础是否健康？ | 状态、水平值 | 财务报表和财务比率 | 不进入健康总分 | 财务健康总分 |
| 模型信号 MSI | 当前模型主要依赖哪些特征，信号方向多强？ | 模型版本对应的预测信号 | TopN、模型权重、特征值 | 仅当模型选中时出现 | 信号强度和贡献分布 |
| 增长潜力 CGPS | 公司最近是否出现可持续改善？ | 趋势、变化值 | 单季度变化、同比加速度、同行分位 | 不包含 | 增长潜力总分 |
| 估值位置 | 股票当前贵不贵？ | 市场时点 | PE、PB、PS及其行业和历史分位 | 独立评分 | 估值位置分 |

统一边界：

```text
FHS       = Level：经营质量的当前水平
MSI       = Model：模型信号及其解释
CGPS      = Delta：经营指标的变化和改善
Valuation = Price：当前价格位置
```

# 3. 财务健康度 FHS

## 3.1 产品定义

财务健康度用于评估企业已经形成的、相对稳定的经营质量和财务安全性。

财务健康度不负责判断：

- 股票价格是否便宜；
- 下一季度是否加速；
- 模型是否看好；
- 未来收益率是否更高。

## 3.2 五个核心维度

### 3.2.1 盈利能力，25%

回答的问题：

> 企业的核心经营活动能否持续产生利润？

推荐因子：

- ROIC，优先；
- ROE，ROIC不可用时使用；
- ROA，适用于重资产或特定行业；
- 营业利润率或净利率。

去重规则：

- ROIC、ROE和ROA均属于资本回报类，不无条件并列平均；
- 每个行业profile选择一个主回报指标，其他指标作为补充证据；
- 毛利率主要反映商业结构，不与净利率重复计满权重。

建议公式：

```text
盈利能力 =
60% × 资本回报分
+ 40% × 核心利润率分
```

### 3.2.2 现金流质量，20%

回答的问题：

> 账面利润能否转化为经营现金？

推荐因子：

- 经营现金流 / 营业收入；
- 经营现金流 / 净利润；
- 自由现金流 / 营业收入。

去重规则：

- 经营现金流同比增速不进入财务健康度；
- 同比增速和变化值归入CGPS；
- 经营现金流绝对金额只作为证据，不因企业规模大而加分。

建议公式：

```text
现金流质量 =
50% × 经营现金流收入比
+ 30% × 利润现金含量
+ 20% × 自由现金流率
```

### 3.2.3 资产负债安全，20%

回答的问题：

> 企业当前是否拥有足够的偿债能力和财务缓冲？

推荐因子：

- 资产负债率；
- 净负债率或有息负债率；
- 流动比率；
- 利息保障倍数。

去重规则：

- `debt_to_assets`和`assets_to_equity`高度相关，不同时完整计权；
- 流动比率和速动比率择一作为主指标；
- 金融企业不得使用普通工商企业的资产负债率评分标准。

建议公式：

```text
资产负债安全 =
50% × 杠杆安全
+ 30% × 短期偿债
+ 20% × 利息保障
```

### 3.2.4 经营效率，20%

回答的问题：

> 企业使用资产和营运资本的效率如何？

推荐因子：

- 总资产周转率；
- 应收账款周转率；
- 存货周转率；
- 现金转换周期。

去重规则：

- 总资产周转率与营业收入/总资产只保留一个；
- 应收和存货指标不适用的行业使用行业profile替换，不用零值代替；
- 银行、保险、软件等行业可替换证据，但维度键保持不变。

### 3.2.5 竞争地位与稳定性，15%

回答的问题：

> 企业是否具备稳定经营和维持市场位置的能力？

推荐因子：

- 三年同行收入份额变化；
- 收入波动率；
- 利润率波动率；
- 可选的分红连续性。

去重规则：

- 三年市场份额变化属于长期竞争状态，进入FHS；
- 单季度收入增长和增长加速度进入CGPS；
- 总市值不作为竞争力代理。

## 3.3 财务健康度总分

```text
FHS =
25% × 盈利能力
+ 20% × 现金流质量
+ 20% × 资产负债安全
+ 20% × 经营效率
+ 15% × 竞争地位与稳定性
```

## 3.4 独立估值位置评分

当前估值维度应从财务健康总分中剥离，独立输出：

```text
Valuation Position Score
```

推荐因子：

- PE行业分位；
- PB行业分位；
- PS行业分位；
- 企业自身历史估值分位。

规则：

- 亏损企业的PE自动不可用；
- 缺失PE不以默认值代替；
- 行业分位作为主评分；
- 样本不足时使用明确标记的历史分位或固定区间fallback；
- 估值分不参与FHS。

前端建议：

```text
财务健康度：82
估值位置：64
```

# 4. 模型信号解释 MSI

## 4.1 产品定义

模型信号解释用于回答：

- 模型重点关注什么；
- 各维度贡献了多少；
- 证据方向是正面还是负面；
- 模型信号覆盖是否充分。

MSI不再输出“TopN健康总分”，也不把模型预测贡献解释为企业经营质量。

## 4.2 六个解释维度

保留以下六个维度作为特征解释分组：

- 增长；
- 盈利；
- 现金流；
- 资产安全；
- 估值；
- 经营效率。

这些维度只用于组织和解释模型特征，不使用固定的业务权重。

## 4.3 模型维度权重

每个维度的权重由模型实际贡献决定：

```text
model_dimension_weight(d)
=
Σ abs(feature_contribution_i in d)
/
Σ abs(feature_contribution_all)
```

贡献值来源优先级：

1. 单样本SHAP绝对值；
2. 标准化模型权重 × 特征偏离度；
3. 全局feature importance，必须标记为`GLOBAL_IMPORTANCE_PROXY`；
4. 不使用固定业务权重代表模型贡献。

## 4.4 MSI输出结构

### 4.4.1 模型信号强度

```text
signal_strength = 0–100
```

该值来自模型原生预测输出的标准化结果，不由财务健康公式重新生成。

### 4.4.2 维度贡献分布

示例：

```text
增长信号贡献       42%
盈利信号贡献       23%
估值信号贡献       18%
现金流信号贡献      9%
资产安全信号贡献    5%
经营效率信号贡献    3%
```

### 4.4.3 维度业务证据

每个维度可显示：

```text
business_evidence_score
```

它仅表示模型选中特征从业务方向看处于什么水平，不再聚合成TopN健康总分。

必须分别输出：

- `predictive_direction`：模型预测方向；
- `business_direction`：业务质量方向。

两者不得互相替代。

## 4.5 TopN内部去重

为每个特征定义`feature_family`。

示例：

```text
roe
roe_dt
q_roe
q_dt_roe
```

统一归为：

```text
return_on_equity_family
```

其他典型特征族：

```text
revenue_growth_family
profit_growth_family
margin_family
cash_conversion_family
leverage_family
valuation_pe_family
valuation_pb_family
turnover_family
```

规则：

- 所有TopN特征可以保留用于模型解释；
- 业务证据评分对同一特征族只选一个代表项，或应用特征族权重上限；
- 同一底层字段的alias只保留一个；
- 派生指标必须声明来源字段和去重关系；
- 解释层的去重不得修改模型原始预测结果。

建议解释层上限：

```text
单一feature最大解释占比：20%
单一feature_family最大解释占比：35%
```

# 5. 企业增长潜力 CGPS

## 5.1 产品定义

CGPS用于判断：

> 企业相对自身历史和同行是否正在出现经营改善。

CGPS只使用：

- 变化；
- 加速度；
- 增量；
- 质量改善；
- 风险恶化。

CGPS不使用单纯的ROE、毛利率、资产负债率绝对水平，因为这些属于财务健康度。

## 5.2 六个核心维度

### 5.2.1 需求加速，25%

推荐因子：

- 单季度收入增长加速度；
- 最近三个季度收入增速趋势；
- 同行收入份额的短期变化趋势。

主公式：

```text
revenue_acceleration =
g_rev(t) - g_rev(t-1)
```

```text
需求加速 =
60% × 收入增长加速度分位
+ 40% × 增长趋势一致性分位
```

去重规则：

- 收入增速水平保留为证据，不与收入增长加速度同时高权重计分；
- 长期三年市场份额变化归入FHS；
- CGPS只使用短期趋势变化。

### 5.2.2 订单能见度，15%

推荐因子：

- 合同负债/TTM收入的同比变化；
- 预收款/TTM收入的同比变化。

建议公式：

```text
订单能见度 =
70% × 合同负债率变化
+ 30% × 预收款率变化
```

去重规则：

- 合同负债不具有订单含义的行业标记为不适用；
- 合同资产不作为正向订单因子；
- 合同负债和预收款来自同一会计映射时，只采用合同负债主指标。

### 5.2.3 盈利杠杆改善，20%

将营业利润增长转换为相对收入增长的利润改善：

```text
operating_leverage_gap =
营业利润增速 - 营业收入增速
```

建议公式：

```text
盈利杠杆改善 =
60% × operating_leverage_gap分位
+ 40% × 核心利润率变化分位
```

去重规则：

- 制造业优先使用毛利率变化；
- 服务业可优先使用营业利润率变化；
- 净利率变化作为核对证据；
- 毛利率、营业利润率和净利率不同时完整计权。

### 5.2.4 利润质量改善，15%

推荐因子：

- 扣非利润占比变化；
- 非经常性损益占比变化；
- 利润与现金流匹配度变化。

建议公式：

```text
利润质量改善 =
50% × 扣非利润占比改善
+ 30% × 非经常性损益占比下降
+ 20% × 利润现金匹配改善
```

去重规则：

- 扣非利润增长本身不重复计入；
- 收入增长、营业利润增长和扣非利润增长不作为三组独立高权重增长因子。

### 5.2.5 现金实现改善，15%

推荐因子：

- `Δ(销售收现/营业收入)`；
- `Δ(经营现金流/营业收入)`；
- `Δ(经营现金流/利润)`。

建议公式：

```text
现金实现改善 =
40% × 销售收现率变化
+ 40% × 经营现金流率变化
+ 20% × 现金利润匹配变化
```

去重规则：

- 现金转换的绝对水平归入FHS；
- 现金转换比率的变化归入CGPS。

### 5.2.6 投资验证与风险约束，10%

基础投资准备因子：

- 研发强度变化；
- 资本开支强度变化；
- 在建工程强度变化。

投资准备必须经过需求与现金验证：

```text
如果需求加速 < 50：
    投资准备分最多为50

如果现金实现改善 < 40：
    投资准备分最多为40
```

风险扣减候选：

- 应收增速超过收入增速；
- 存货增速超过收入增速；
- 杠杆上升；
- 流动性下降。

最终公式：

```text
S6 = max(0, validated_investment_score - risk_penalty)
```

此设计避免出现扩产越多、在建工程越高，增长潜力分就无条件越高的问题。

## 5.3 CGPS总分

```text
CGPS =
25% × 需求加速
+ 15% × 订单能见度
+ 20% × 盈利杠杆改善
+ 15% × 利润质量改善
+ 15% × 现金实现改善
+ 10% × 投资验证与风险约束
```

原资产负债与营运安全不再作为正向维度重复加分，而是作为风险约束或扣分项。FHS负责评估安全水平，CGPS只评估风险是否正在恶化。

# 6. 三个评分体系的指标归属

同一个底层指标可以被三个体系读取，但必须采用不同的评分语义。

| 原始指标 | FHS | MSI | CGPS |
|---|---|---|---|
| 营收同比 | 不作为主要健康因子 | 模型选中时解释 | 使用加速度或趋势 |
| ROE | 当前盈利水平 | 模型选中时解释 | 使用ROE变化，不用绝对值 |
| 毛利率 | 稳定盈利证据 | 模型选中时解释 | 使用毛利率同比变化 |
| 经营现金流/收入 | 当前现金质量 | 模型选中时解释 | 使用该比率的变化 |
| 资产负债率 | 当前财务安全 | 模型选中时解释 | 仅将杠杆恶化作为风险 |
| 资产周转率 | 当前经营效率 | 模型选中时解释 | 使用周转率变化 |
| PE/PB/PS | 独立估值卡片 | 模型选中时解释 | 不使用 |
| 合同负债/收入 | 通常不使用 | 模型选中时解释 | 使用订单能见度变化 |
| 研发/收入 | 可作为证据，不直接加分 | 模型选中时解释 | 使用变化且经需求和现金验证 |

# 7. 统一技术去重机制

## 7.1 Schema建议

建议在feature schema中增加：

```yaml
feature_key: roe_dt
feature_family: return_on_equity
economic_concept: capital_return
score_roles:
  - financial_health_level
  - model_evidence
allowed_transform:
  financial_health_level: peer_percentile
  model_evidence: model_native
cgps_usage: prohibited
source_fields:
  - fina_indicator.roe_dt
dedup_priority: 100
max_family_weight: 0.35
```

## 7.2 四层去重

### 第一层：字段去重

解决多个名称实际指向同一字段的问题，例如：

```text
gross_margin
grossprofit_margin
gross_profit_margin
```

统一映射到：

```text
canonical_feature_key
```

### 第二层：公式去重

识别公式不同但表达相似概念的指标，例如：

```text
debt_to_assets
assets_to_equity
equity_multiplier
```

统一归入：

```text
feature_family = leverage
```

### 第三层：经济含义去重

识别不同字段但高度重复表达同一经营事实的指标，例如：

```text
营业利润增长
净利润增长
扣非利润增长
```

统一归入：

```text
economic_concept = earnings_growth
```

每个维度对同一`economic_concept`设置权重上限。

### 第四层：评分体系去重

使用`score_role`限制指标在不同评分中的用途：

```text
LEVEL
DELTA
MODEL_ONLY
VALUATION_ONLY
RISK_ONLY
EVIDENCE_ONLY
```

示例：

```yaml
pe_ttm:
  score_role:
    - VALUATION_ONLY
    - MODEL_ONLY

revenue_yoy:
  score_role:
    - MODEL_ONLY
    - DELTA_INPUT

debt_to_assets:
  score_role:
    - LEVEL
    - MODEL_ONLY
    - RISK_INPUT
```

# 8. 归一化原则

## 8.1 推荐顺序

```text
行业同行分位
→ 同期全市场分位fallback
→ 版本化固定区间fallback
→ NOT_AVAILABLE
```

规则：

- 行业样本达到最低门槛时优先使用行业分位；
- 使用全市场或固定区间fallback时必须返回状态；
- 百分位内部统一为`[0,1]`或统一为`[0,100]`，不得静默猜测；
- 金额、百分比、百分点、倍数和分位必须明确单位；
- 非单调指标应使用`target_range`或`non_monotonic`变换，不强制按越高越好处理。

# 9. 覆盖率和缺失规则

统一原则：

```text
缺失值 ≠ 0
缺失值 ≠ 50
不适用 ≠ 缺失
模型未选中 ≠ 数据缺失
低覆盖 ≠ 有效总分
```

## 9.1 FHS门槛

```text
总有效权重 >= 80%
且盈利能力、现金流质量、资产负债安全三个核心维度有效
```

不满足时：

```text
score = null
status = INSUFFICIENT_DATA
```

## 9.2 MSI门槛

```text
feature_weight_coverage >= 70%
```

低于门槛时：

- 仍可展示已取得的特征和贡献；
- 不输出总信号强度等级；
- 状态标记为`LOW_COVERAGE`或`INSUFFICIENT_DATA`。

## 9.3 CGPS门槛

```text
总有效权重 >= 80%
且需求加速、盈利杠杆改善、现金实现改善三个核心维度有效
```

不满足时：

```text
score = null
status = INSUFFICIENT_DATA
```

## 9.4 可用性状态

建议统一状态：

```text
AVAILABLE
PARTIAL
NOT_AVAILABLE
INSUFFICIENT_DATA
NOT_APPLICABLE
MISSING
INVALID
STALE
DEGRADED
UNMAPPED
EVIDENCE_ONLY
```

# 10. 前端展示建议

三个评分不使用相同的雷达图、相同等级和相同解释模板。

## 10.1 财务健康度卡片

# 12. 核心验收规则

- FHS只评估经营质量的当前水平；
- 估值只评估价格位置；
- MSI只解释模型，不冒充健康度；
- CGPS只评估经营变化和改善；
- 同一底层字段的alias不得重复计权；
- 同一`feature_family`和`economic_concept`必须设置去重或权重上限；
- 同一个经济概念在同一个评分中最多获得一次主要权重；
- 同一指标跨评分使用时必须分别采用`LEVEL`、`DELTA`、`MODEL`、`VALUATION`或`RISK`语义；
- 缺失和不适用不得用0分或50分静默填补；
- 每项评分必须返回版本、报告期、as-of时点、数据覆盖率和可用性状态；
- 不同版本、不同模型和不同覆盖率的结果不得被标记为直接可比。
