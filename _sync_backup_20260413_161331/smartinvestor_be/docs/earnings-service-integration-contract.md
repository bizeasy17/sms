# BE Integration Contract: Call Earnings Service and Serve FE

## 1. Integration Goal

Target architecture:

- FE calls BE API only.
- BE calls Earnings Forecast Service internally.
- BE normalizes and returns stable response to FE.

This avoids FE coupling to model internals and enables safer model upgrades.

## 2. Call Chain

1) FE -> BE public endpoint
2) BE -> Earnings service /api/forecast/signal/
3) BE applies business guards (timeout/retry/fallback/cache)
4) BE returns normalized payload to FE

## 3. Upstream API (BE -> Earnings)

Endpoint:

- GET http://<earnings-host>/api/forecast/signal/?ts_code=<code>

Upstream fields used by BE:

- result.ts_code
- result.trade_date
- result.model_version
- result.feature_data_source
- result.be_payload.signal_score
- result.be_payload.action
- result.be_payload.risk_level
- result.valuation_mapping (optional for explainability)

## 4. Downstream API (BE -> FE) Recommended Contract

Response example:

{
  "code": 0,
  "message": "ok",
  "data": {
    "ts_code": "600519.SH",
    "signal_score": 67.4,
    "action": "BUY",
    "risk_level": "MEDIUM",
    "model_version": "earnings_q1_v1_2_0",
    "asof_date": "2026-03-28",
    "explain": {
      "stance": "BUY",
      "confidence": "MEDIUM",
      "prob_component": 42.7,
      "earnings_component": 24.7
    }
  }
}

Notes:

- FE should only depend on BE fields above.
- Do not expose raw training targets or unstable internals to FE.

## 5. Error and Fallback Strategy

### 5.1 BE timeout/retry

- timeout: 3-5 seconds
- retry: max 1 retry for transient failure

### 5.2 Degrade rules

If upstream fails, BE should return:

- latest cached prediction for ts_code (if cache hit)
- else action=HOLD, risk_level=MEDIUM, signal_score=null
- include degrade flag in response

Example degrade block:

"degrade": {
  "enabled": true,
  "reason": "upstream_timeout"
}

## 6. Version Governance in BE

BE should persist these metadata fields per response snapshot:

- model_name
- model_version
- dataset_version
- run_id (if available)
- rules_version

These can be obtained from serving pointer or model registry generated by earnings service.

## 7. Release Procedure

1) Train candidate model and validate offline output.
2) Run monthly refresh in earnings service and write snapshots.
3) BE smoke test against snapshot read API.
4) FE consumes unchanged BE contract.

## 8. Security and Observability

- Use internal network allowlist between BE and earnings service.
- Log request id, ts_code, latency, upstream status, model_version.
- Add alarm on upstream error rate and p95 latency.

## 10. Implemented Minimal Endpoint (Current)

Implemented endpoint in BE:

- GET /api/earnings/signal/<ts_code>/

Behavior:

- Calls upstream GET /api/forecast/signal/?ts_code=<code>
- Maps upstream result.be_payload + valuation_mapping to FE-friendly data object
- Uses timeout/retry from settings:
  - EARNINGS_SERVICE_BASE_URL
  - EARNINGS_SERVICE_TIMEOUT_SECONDS
  - EARNINGS_SERVICE_RETRY_COUNT
  - EARNINGS_SIGNAL_CACHE_SECONDS

Current degrade semantics:

- If upstream fails and cache hit:
  - code=0, message=ok
  - degrade.enabled=true
  - degrade.reason=upstream_error_cache_hit
- If upstream fails and no cache:
  - code=0, message=ok
  - data.action=HOLD, data.risk_level=MEDIUM, data.signal_score=null
  - degrade.enabled=true
  - degrade.reason=upstream_error_default

Example request:

- GET /api/earnings/signal/600519.SH/

## 11. Snapshot-First Serving Mode (Recommended)

To avoid FE latency from online inference, earnings service now owns snapshot-first mode:

1) Monthly job runs in earnings service and writes per-symbol signals into table `earnings_signal_snapshot`.
2) Earnings service exposes read API:
  - `GET /api/forecast/signal/?ts_code=<code>`
3) BE calls this read API and maps to FE contract.
4) If snapshot missing or upstream fails, BE returns default HOLD payload with degrade metadata.

Monthly refresh command example:

- In earnings service: `python manage.py refresh_signal_snapshot --scope 60,00,30,68 --batch-key monthly_202603`
